# Architectural Definition of Done

An architectural module is ready for implementation only when all applicable cells below are complete. This protects against a pipeline that looks complete but lacks evidence, failure, security, or operating behavior.

| Module | Requirement/contract | Data ownership | Security boundary | Failure behavior | Test evidence | Observability | Deployment/documentation | Done when |
|---|---|---|---|---|---|---|---|---|
| Intake and source registry | RawEvent/Source; REQ-001, 005, 012, 014 | evidence store and metadata registry | untrusted ingress, auth/rate/size limits | reject-before-accept audited; post-accept retain/retry | receipt/hash/limits/idempotency tests | intake rate/rejections/accepted evidence | listener/config/runbook | accepted events have durable evidence or explicit audited rejection |
| Parser runtime | ParsedEvent/Parser; REQ-002, 005, 009, 012 | parser registry and processing state | isolated worker and trusted packs | partial/failed parse becomes explicit warning/DLQ | fixture/fuzz/timeout/regression tests | latency/success/limits/drift metrics | pack lifecycle/sandbox runbook | parser output has version, locators, residue, and bounded execution |
| Normalization/schema | NormalizedEvent/Mapping/Schema; REQ-003, 008 | schema/mapping registry | approval/versioning/input validation | warning/quarantine policy explicit | mapping/type/equivalence/compatibility tests | quality/coverage/validation metrics | schema evolution guide | UCE preserves origin/unmapped fields and deterministic pinned result |
| Evidence and lineage | Lineage/Audit; REQ-001, 004 | object evidence/manifests/lineage store | evidence read/export and signing keys | mismatch/absence observable; no false verification | round-trip/tamper/trace/restore tests | verification failure/retrieval metrics | custody/restore/export runbook | raw-to-field trace and integrity status are retrievable |
| Streaming/DLQ/replay | ReplayJob/DLQ; REQ-001, 013, 014 | broker/DLQ/replay result namespace | source quotas, replay authorization | bounded retry/quarantine/checkpoint/cancel | order/duplicate/recovery/replay tests | lag/DLQ/retry/checkpoint metrics | capacity/replay runbook | failure keeps evidence and replay does not overwrite history |
| Storage and outputs | UCE/projection contracts; REQ-006, 007, 008, 013 | metadata/evidence/search/lake stores | per-store privileges and export controls | projection failure isolated/retried | backup/restore/export/contract tests | store/delivery health | retention/backup/adapter documentation | data purpose/retention/query path is explicit and tested |
| AI/onboarding | source/parser/mapping contracts; REQ-005, 009 | proposal/review registry | untrusted sample/model/bundle boundaries | AI unavailable means deterministic fallback | proposal/approval/offline/prompt-injection tests | confidence/approval/model health | onboarding/AI capability guide | no automatic publication and all proposals are traceable |
| API/frontend | API contracts; REQ-004, 006 | server API and client state | OIDC/RBAC/field masking | safe error/degraded/empty states | contract/e2e/accessibility/authz tests | request/error/job status metrics | UX/API docs | user can investigate raw-to-normalized trace under correct permissions |
| Deployment/security | deployment/bundle policy; REQ-010, 011 | local registry/secrets/operator assets | air-gap, TLS, SBOM/signing, admin controls | fail-closed bundle verification and documented degraded mode | network-denied/import/scan/authz/restore tests | component/bundle/air-gap health | Compose/Kubernetes path and air-gap runbook | core path operates locally without Internet dependency |

Any exception must be time-bounded, risk-owned, visible in the risk register, and approved through an ADR or documented acceptance process. It cannot silently weaken a hard invariant.
