3. CORE ARCHITECTURAL PRINCIPLE
======================================================================

ULPF MUST NOT become:

"if vendor == X:
    regex X
elif vendor == Y:
    regex Y"

Do not create a giant conditional parser.

Use:

Source
  ->
Transport/Frame
  ->
Format Detector
  ->
Source/Vendor Detector
  ->
Parser Registry
  ->
Parser Pack
  ->
Extractor
  ->
Semantic Mapper
  ->
Canonical Event
  ->
Validator
  ->
Output

Core engine = stable.

Parser packs = extensible.

Mappings = declarative where practical.

Rules = versioned.

Schemas = versioned.

Vendor-specific syntax = isolated from core.

5. RAW DATA PRESERVATION
======================================================================

The raw event must remain authoritative.

Parsing MUST NEVER overwrite raw bytes.

Every Parsed/Canonical event must retain sufficient reference to the original
evidence.

Depending on the frozen architecture, preserve:

- raw event bytes or immutable evidence reference,
- SHA-256,
- source information,
- ingestion ID,
- event correlation ID,
- parser ID,
- parser version,
- parse timestamp,
- schema version.

Example conceptual model:

{
  "event_id": "...",
  "raw_evidence_ref": "...",
  "raw_sha256": "...",
  "parser": {
      "id": "...",
      "version": "...",
      "confidence": ...
  },
  "canonical": {...},
  "attributes": {...}
}

Do not unnecessarily duplicate huge raw payloads in every downstream object
if the evidence architecture defines a reference mechanism.

Lossless evidence has priority.

6. RECORD FRAMING
======================================================================

Implement framing as a first-class concern.

Support where required:

- line-delimited records,
- LF,
- CRLF,
- single-record payloads,
- multiline records,
- stack traces,
- CRI partial records,
- prefixed continuation lines,
- JSON lines,
- syslog messages,
- framed transport records.

The parser must not assume:

"one newline = one event"

Implement a clear framing interface.

Example conceptual interface:

FrameDetector
RecordFramer
FramingResult

Framing must be bounded.

Never allow an attacker to create unbounded memory growth through an
unterminated multiline record.

Define:

- max record bytes,
- max line bytes,
- max multiline lines,
- max nesting depth where applicable,
- timeout policy,
- overflow behavior.

======================================================================
38. DEAD-LETTER / FAILURE ROUTING
======================================================================

Possible states:

======================================================================
39. PARSER FAILURE MUST NEVER DESTROY RAW DATA
======================================================================

This rule is absolute.

If parser fails:

raw event remains intact.

If normalization fails:

parsed/raw information remains intact.

If schema validation fails:

the original evidence remains available.

======================================================================
40. SECURITY: REGEX / ReDoS
======================================================================

All regex-based parsing must be reviewed for ReDoS.

Avoid catastrophic patterns.

Prefer:

- anchored patterns
- bounded quantifiers
- explicit tokenization
- parsers over giant regexes

The adversarial regex stress fixture MUST be used.

Do not claim ReDoS resistance without testing.

======================================================================

MAX_FIELDS
MAX_JSON_STRING_LENGTH
MAX_ARRAY_LENGTH
MAX_PARSE_TIME where feasible

These must be configuration-driven.

Never trust source-controlled payloads.

======================================================================
42. SECURITY: XML
======================================================================

Disable:

external network access
unsafe entity resolution

Test XML security.

======================================================================
43. SECURITY: PATH HANDLING
======================================================================

Parser packs and fixture paths must not permit:

untrusted code execution

======================================================================
44. SECURITY: PARSER PACK TRUST MODEL
======================================================================

Design parser packs so that future air-gapped deployment can enforce:

- schema validation
- signed/verified packs later
- allowed parser IDs
- version pinning
- deterministic execution
- no network access from parser logic
- no arbitrary shell execution

Phase 3 does not necessarily need full cryptographic signing implementation
if reserved for later security hardening, but the architecture must not
prevent it.

======================================================================
45. DETERMINISTIC PARSING
======================================================================

Given identical:

raw bytes
parser pack version
configuration
runtime version

the parser must produce identical results.

Avoid nondeterministic logic.

This is mandatory for:

testing
forensics
auditing
reproducibility

======================================================================
46. PARSER PRIORITY / AMBIGUITY
======================================================================

Multiple parsers may match one event.

Implement deterministic tie-breaking.

Possible order:

1. exact source/vendor/product match
2. exact format match
3. required signature fields
4. parser confidence
5. parser priority
6. version policy

Never select arbitrarily.

Record the rejected candidates where useful.

Phase 3 parsing must remain:

Do not make Phase 3 dependent on an external API.

and bounded batches.

Do not require full dataset loading.

======================================================================
106. CONCURRENCY
======================================================================

Phase 3 should be concurrency-safe where architecture requires it.

Avoid mutable global parser state.

Parser registry may be initialized once but should behave safely.

======================================================================
107. THREAD / PROCESS SAFETY
======================================================================

Parsers should avoid:

- global mutable buffers
- cross-event state
- shared temporary files
- race-prone caches

Multiline framing may maintain bounded per-stream state.

Make stream state explicit.

======================================================================

2 valid
3 malformed
4 valid
5 valid

2 parsed
3 rejected/partial
4 parsed
5 parsed

No stream-wide crash.
